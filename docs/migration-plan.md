## 范围和设计

- 源码以公司提供的合并文件还原结果为基线，保留版权头、Services/Service 和 Services/Package 布局。
- 保留配置规则、DAGBuilder、DAGExecutor、TaskScheduler 和 SQLTaskRunner；不引入原 GitHub 的领域分层、私有统计表、发布对账、迟到重算或自动历史回填框架。
- 使用同一 Python 解释器的一次性 XMS helper，解密后 Base64 解码 PMS，按服务名和用户名唯一选择密码；凭据不出现在命令参数、日志、Git 中。
- 标准库 HTTP POST 执行 ClickHouse SQL，使用服务注入的 HTTP(S) 端点；移除业务链路对 kubectl、Java 的依赖，不引入 Redis 选主。
- SQLite 只保存窗口状态、尝试次数、计划游标和部署绑定；本机 flock 保证同一状态目录单写入者。
- 成功窗口跳过；只自动重试确认尚未发送的连接错误；超时、断线、进程中断及无法分类的写入失败标记 UNKNOWN，核验后由显式命令处理。
- 上游依赖覆盖下游时间范围内的全部子窗口；定时延迟从持久游标补齐；首次运行只处理 coverage_start 之后的完整数据窗口。
- 前台 exec 启动，SIGTERM 停止新任务并等待当前有界 SQL；探针读取进程心跳，不读取密码或查询数据库。
- 部署要求一个调度实例、持久状态、Recreate 和固定状态节点（沿用 hostPath 时）。本地锁不承诺跨节点选主。
- Redis消息先原子转processing，再将ready事实持久化到SQLite，提交后ACK；cron、就绪事件及手工执行统一经过门控与现有执行账本，不用SETNX代表SQL成功。
- 本阶段仅修复 SQL 固定历史时间和 SELECT/INSERT 列数不匹配两项执行缺陷；其它统计口径问题列入已知问题，单独逐项迁移。
