# 在线时间段补算

用户要求服务继续运行，通过命令提交后台补算；支持单任务及全部任务。
目的是在迟到数据补入后主动汇聚历史窗口，并能查询进度。

## 接口和时间

`dconv --backfill --task NAME|--all-tasks --from TIME --to TIME`
提交左闭右开数据范围；时间必须含时区，按应用时区拆成完整窗口。
单任务必须对齐其周期；全部任务仅处理完全包含的窗口，明确列出无完整窗口的任务。
禁止未来窗口、空范围及超过 10000 个窗口的请求。`--dry-run` 只读预览。
默认跳过已成功窗口，`--recompute` 明确重新清理并汇聚已成功窗口。
`--request-id` 支持重复提交幂等；`--backfill-status ID` 分页查询进度。

## 执行与持久化

命令只向状态目录的独立 `backfill.sqlite3` 提交请求，不争用主账本的生命周期锁，
不获取 Redis 主租约，不执行 ClickHouse SQL。命令应在当前主实例所在 Pod 执行，
请求库与状态库都必须保留在持久卷；不提供跨 Pod 请求路由。

服务主调度线程每轮正常调度结束后执行至多一个补算窗口，继续使用现有租约保护的
SQL runner。无额外 SQL 执行线程，不与正常汇聚并发写同一窗口；单个慢补算仍会延迟
下一轮调度，不承诺零延迟。任务按 DAG 拓扑顺序、各任务按时间升序处理。
同周期依赖仍需成功，批次内的依赖优先使用本批次结果；跨周期只排序，不新增成功门槛。
显式手动补算使用已有数据，不等待历史 DWD 信号。允许处理当前覆盖起点之前的完整窗口，
不改调度游标及覆盖起点；退休记录、RUNNING、UNKNOWN 不被强制覆盖。

主账本同事务登记唯一补算条目 ID、query_id、DISPATCHED 检查点、执行历史和实例 RUNNING。
结束时主实例、历史与条目结果同事务提交，再同步队列结果；同步失败可按条目 ID 重取，
不能重复执行 SQL。补算中断后的 RUNNING 转 UNKNOWN，排除普通自动恢复路径。
失败不进入正常重试队列；修复后由操作者提交新批次，UNKNOWN 先核实远端结果。
请求绑定当前配置与 SQL 摘要，服务快照不一致时明确阻断该请求，不改变正常服务启动策略。

## 验证与限制

覆盖时间边界、DST、全部任务顺序、默认去重和显式重算、CLI 与服务并存、
请求幂等、同周期依赖、结果不确定、崩溃后结果同步、游标不变与正常调度优先。
使用本地模拟 runner，不连接生产数据库。
重算沿用现有先清理再写入 SQL，二者不是数据库事务，失败可能留下该窗口暂时为空。
清理目标必须与 INSERT 目标一致；实际 ClickHouse 表引擎、分片与数据保留由部署方保证，
本仓库不创建表、不修改业务汇聚 SQL。
